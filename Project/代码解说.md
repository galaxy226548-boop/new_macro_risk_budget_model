## 1. 整體流程一覽

```
Excel 數據文件
    ↓
讀取 → 計算每日對數收益率 → 整理成「日期×資產」表格 (ret_sub)
    ↓
確定每個月末的調倉日 (rebalance_dates)
    ↓
【主循環】對每個調倉日：
   ① 用過去6個月數據 → 計算風險平價權重
   ② 計算換手率和手續費
   ③ 模擬持倉期收益（Buy & Hold，即持有期間不動，自然漂移）
   ④ 把手續費扣在新持倉第一天
   ↓
計算績效指標（年化收益、最大回撤、夏普比率等）
    ↓
用同樣框架跑三個基準模型（波動倒數 / 等權 / 60股40債）
    ↓
保存結果到 Excel 和 JSON
```

## 3. 數據讀取與整理

### 原始數據長什麼樣？
Excel 是「長表」格式：每行是一條「某資產某天的收盤指數」記錄。

```
Trddt      | Indexcd | Clsidx
2023-01-03 | HS300   | 3871.25
2023-01-03 | CBA02001| 208.43
2023-01-04 | HS300   | 3906.11
...
```

### 計算對數收益率
```python
df["log_ret"] = df.groupby("Indexcd")["Clsidx"].transform(
    lambda x: np.log(x) - np.log(x.shift(1))
)
```
**邏輯**：按每個資產分組（`groupby`），對每組的收盤指數算 `ln(今天) - ln(昨天)`。
這就是對數收益率，等價於 `ln(今天/昨天)`。

> **為什麼用對數收益率而不用普通收益率？**  
> 對數收益率可以直接相加（多天的對數收益率加起來 = 這段期間的總對數收益率），
> 普通收益率不行。這讓後面的「累計收益」計算非常方便。

### 整形成「寬表」
```python
ret_sub = df.pivot(index="Trddt", columns="Indexcd", values="log_ret")
```
把長表變成：行 = 日期，列 = 各資產，值 = 當日對數收益率。

```
Trddt      | HS300   | CBA02001 | ...
2023-01-04 | 0.00898 | 0.00123  | ...
2023-01-05 | -0.0045 | 0.00089  | ...
```
這個表叫 `ret_sub`，後面幾乎所有計算都基於它。

## 4. 調倉日的確定

```python
rebalance_dates = ret_sub.groupby(pd.Grouper(freq="ME")).apply(lambda x: x.index.max())
rebalance_dates = rebalance_dates[rebalance_dates >= STRATEGY_START]
rebalance_dates = rebalance_dates[rebalance_dates < ret_sub.index.max()]
```

**邏輯**：
1. 按月份分組（`freq="ME"` 是 Month End）
2. 每個月取最後一個有數據的交易日 → 這就是「月末調倉日」
3. 只保留策略起點之後的調倉日
4. 去掉最後一天（避免持倉段為空）

## 5. 風險平價求解器（最核心的函數）

**函數名**：`risk_parity_weights_from_window(ret_window, w0)`

### 風險平價是什麼意思？
普通「等權」是每個資產投一樣多的錢。
「風險平價」是讓每個資產**貢獻一樣多的風險**。

波動大的資產（比如股票）少配一點，波動小的資產（比如債券）多配一點，
使得它們對組合風險的貢獻（TRC）相等。

### 核心計算步驟

**第一步**：計算協方差矩陣 `Sigma`（衡量資產之間的波動和相關性）
```python
Sigma = ret_window.cov().values
```

**第二步**：對角加載（數值穩定性處理）
```python
eps = 1e-6 * avg_var
Sigma = Sigma + np.eye(n_local) * eps
```
給對角線加一個很小的數，防止矩陣「退化」導致計算出錯。不影響經濟含義。

**第三步**：定義目標函數（讓所有資產的風險貢獻儘量相等）
```python
def obj_w(w):
    R = sqrt(w @ Sigma @ w)      # 組合整體波動率
    MRC = (Sigma @ w) / R        # 邊際風險貢獻（每多加一點這個資產，風險增加多少）
    TRC = w * MRC                # 總風險貢獻（= 持倉比例 × 邊際風險貢獻）
    return variance_of(TRC)      # 最小化 TRC 的方差 → TRC 越平均越好
```

**第四步**：用優化器（SLSQP）求解
約束：所有權重加起來 = 1，且每個 ≥ 0（做多限制）。

**第五步**：分層兜底
- 優化成功 → 返回優化結果
- 優化失敗 → 返回上一期的權重 `w_prev`
- 連上一期都沒有 → 返回等權

## 6. 回測主循環（最重要的部分）

### 循環前的初始化
```python
weights_by_reb = []                    # 存每次調倉的目標權重
port_log_ret = pd.Series(...)          # 存每天的組合對數收益率
w_prev_end = np.zeros(n)               # ⚠️ 上次調倉後的漂移權重，初始為零（空倉）
turnover_gross_list = []               # 存每次調倉的換手率
all_daily_eff_w_segs = []             # 存每天的實際持倉比例
```

> **`w_prev_end` 為什麼初始化為零而不是等權？**  
> 因為策略一開始是「空倉」，第一次買入的換手率應該是 100%（全額建倉）。
> 如果初始化為等權，會低估第一次建倉的手續費。

### 每次循環做什麼？（共 8 步）

**① 取回望窗口**
```python
t_start = t_reb - pd.DateOffset(months=6)
ret_window = ret_sub.loc[t_start:t_reb, assets]
```
用調倉日往前推 6 個月的日收益數據，作為估計協方差的樣本。

**② 計算本次目標權重**
```python
w_t = risk_parity_weights_from_window(ret_window, w0=w_prev)
```
調用風險平價求解器，輸入 6 個月窗口數據，輸出各資產的目標配置比例。

**③ 確定持倉期**
```python
t_effective = idx_dates[pos + 1]   # 生效日 = 調倉日的下一個交易日
t_hold_end = 下一個調倉日（或數據末尾）
hold_slice = ret_sub.loc[t_effective:t_hold_end, assets]
```
新權重在調倉日的 **後一個交易日** 才生效（T+1 執行）。
持倉一直到下次調倉日收盤（因為下次調倉日的新權重第二天才生效）。

**④ 計算換手率和手續費**
```python
gross_turnover = sum(|w_t - w_prev_end|)   # 所有資產買賣比例之和
fee_t = FEE_RATE * gross_turnover           # 手續費 = 萬分之一 × 換手
```
`w_prev_end` 是上次調倉後、到本次調倉前的「漂移後權重」（因為資產價格變動，
實際持倉比例已經偏離了上次設定的目標比例）。

> **例子**：上次設定 HS300 = 40%，但過去一個月 HS300 漲了很多，
> 實際持倉比例可能已經漂移到 45%。計算換手要用這個 45%，不是 40%。

**⑤ 模擬 Buy & Hold 段內收益**
```python
asset_rel = np.exp(hold_slice.cumsum())    # 每個資產相對段首的累計淨值
port_rel = asset_rel.values @ w_t          # 組合的累計淨值 = 加權平均
```
`cumsum()` 是累加，`exp()` 把對數收益率轉回倍數（淨值）。
`@ w_t` 是矩陣乘法：`Σ (資產淨值 × 該資產初始權重)`。

這叫 **Buy & Hold**：調倉後不再干預，讓各資產的權重隨市場價格自然漂移。

**⑥ 計算每日漂移有效權重（新增）**
```python
daily_eff_w = asset_rel.values * w_t                              # 分子
daily_eff_w = daily_eff_w / daily_eff_w.sum(axis=1, keepdims=True)  # 每日歸一化
```
記錄每一天「各資產實際佔組合的比例」。
第一天 ≈ 目標權重，之後隨著資產漲跌逐漸偏離。

**⑦ 把手續費扣在新持倉第一天**
```python
seg_log_ret.iloc[0] += np.log(1.0 - fee_t)
```
等價於：第一天的組合淨值 × (1 - 手續費率)。
用對數形式是因為我們的收益率是對數收益率，可以直接相加。

**⑧ 更新 `w_prev_end` 到期末漂移值**
```python
last_rel = asset_rel.iloc[-1].values          # 段末各資產的相對淨值
w_prev_end = (w_t * last_rel)
w_prev_end = w_prev_end / w_prev_end.sum()   # 歸一化
```
記錄持倉期末的實際比例，供下次調倉計算換手率使用。

## 7. 績效指標計算

**函數**：`_calc_one_period_metrics(series, turnover_series, label)`

| 指標 | 計算方式 | 含義 |
|------|----------|------|
| `AnnReturn` | `exp(日均對數收益 × 252) - 1` | 年化收益率 |
| `AnnVolatility` | `日收益標準差 × √252` | 年化波動率（風險） |
| `MaxDrawdown` | `min(NAV / 歷史最高NAV - 1)` | 最大回撤（從最高點跌了多少） |
| `Sharpe` | `(AnnReturn - 無風險利率) / AnnVolatility` | 夏普比率（每承擔1單位風險的超額回報） |
| `Calmar` | `AnnReturn / |MaxDrawdown|` | 卡馬比率（每單位最大回撤的年化收益） |
| `AnnTurnover` | `期間換手總和 / (交易日數/252)` | 年化換手率 |

指標分兩層輸出：
- `metrics_raw`：原始數值（用於後續計算）
- `metrics`：格式化字符串（用於展示，如 `"12.34%"`）

## 8. 三個基準模型

三個模型都用同一個框架函數 `_run_backtest_with_weight_func(weight_func, label)` 跑，
唯一的區別是傳入不同的「計算權重的函數」。

| 模型 | 權重函數 | 邏輯 |
|------|----------|------|
| **波動倒數（InvVol）** | `_w_inv_vol` | `w_i ∝ 1/σ_i`，波動大的少配 |
| **等權（EqualWeight）** | `_w_equal` | 每個資產分配 `1/n` |
| **60股40債（HB64）** | `_w_64` | HS300=60%，CBA02001=40%，其餘=0 |

`_run_backtest_with_weight_func` 內部邏輯和主循環完全一致，
包括：零向量初始化 `w_prev_end`、手續費計算、Buy & Hold 模擬、每日漂移權重。

**對齊收益序列**：
```python
def _align_series_and_turnover(port_log_ret_local, weights_df_local):
    s = port_log_ret_local.loc[port_log_ret_local.index >= STRATEGY_START].dropna()
    t = weights_df_local.diff().abs().sum(axis=1) / 2.0
    return s, t
```
注意：基準模型的換手率 `t` 是從「目標權重的差」算的（不考慮漂移），
而主模型的換手率是從 `w_prev_end` 算的（考慮了漂移）。
這是一個**不一致**，可以在審閱時留意。

## 10. 最近三個 Bug 修復說明

### Fix 1：初始建倉手續費低估
**問題**：`w_prev_end` 初始化為等權向量，第一次調倉的換手被算成 `|w_目標 - 等權|`，
而不是正確的 `|w_目標 - 0| ≈ 1.0`（從空倉到全額建倉）。

**修復**：
```python
# 之前（錯）
w_prev_end = np.ones(n, dtype="float64") / n

# 修復後（對）
w_prev_end = np.zeros(n, dtype="float64")
```

同一個修復在主循環（line 243）和 `_run_backtest_with_weight_func`（line 504）各做了一次。

---

### Fix 2：新增每日漂移有效權重
**問題**：段內每天的實際持倉比例從未被計算和保存，無法事後輸出或驗證。

**修復**：每次計算完 `asset_rel` 後，立即算出並保存每日漂移權重：
```python
daily_eff_w = asset_rel.values * w_t
daily_eff_w = daily_eff_w / daily_eff_w.sum(axis=1, keepdims=True)
daily_eff_w_df_seg = pd.DataFrame(daily_eff_w, index=hold_slice.index, columns=assets)
all_daily_eff_w_segs.append(daily_eff_w_df_seg)
```
循環結束後拼接：`daily_weights_df = pd.concat(all_daily_eff_w_segs).sort_index()`

---

### Fix 3：統一年化換手率計算
**問題**：
1. Cell 17 有兩行一模一樣的 `ann_turnover = turnover.mean() * 12`（重複且從未被使用）
2. `_calc_one_period_metrics` 用日曆天數 ÷ 365.25 計算年數，不夠準確

**修復**：
```python
# 刪除了兩行重複的 ann_turnover = turnover.mean() * 12

# 函數內改為用實際交易日
trading_days = len(series)
years_actual = trading_days / annual_days      # annual_days = 252
ann_turnover = total_turnover / years_actual
```

### 基準模型層
- [ ] 三個基準模型的換手率計算用的是目標權重差（未考慮漂移），與主模型的方法不同——是否可接受？
- [ ] `_w_64` 的 `assets.index("HS300")` 和 `assets.index("CBA02001")` 是否能正確找到對應資產？

### 輸出層
- [ ] Excel 輸出的日期格式是否為純日期（`YYYY-MM-DD`）而非帶時間的 `Timestamp`？
- [ ] `metrics_raw` 和展示用 `metrics` 的數值是否對應？（`metrics` 是格式化字符串版本）
